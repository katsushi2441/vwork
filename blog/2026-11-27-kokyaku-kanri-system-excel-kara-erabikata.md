名古屋でシステム開発をしている、株式会社エクスブリッジの小嶋です。

顧客管理は、たいていエクセルの顧客台帳から始まります。会社名、担当者、電話番号、最後に連絡した日、メモ。1人か2人で回しているうちはそれで十分ですが、人ややり取りが増えると、ファイルを同時に開けない、どれが最新か分からない、メモの欄が長すぎて読めない、といったことが起きて、「顧客管理システム」を探し始めることになります。

CRM（顧客管理）や SFA（営業支援）と呼ばれるシステムはどれも機能の一覧が長く、比べにくいと思います。この記事では、エクセルの台帳から移るときに見ておきたいところを5つに分けて書き、そのあとで当社の顧客管理システムを使い方の違いで分けて紹介します。整体院・整骨院の場合については、[整体の顧客管理の記事](https://exbridge.jp/vibeblog/2026-11-07-seitai-kokyaku-kanri.html)に別にまとめています。

## エクセルの台帳から移るときに見る5つ

### 1. 何人で、同時に書くか

エクセルの台帳でいちばん先に困るのは、複数の人が同時に書けないことです。誰かが開いているとほかの人は読み取り専用になり、手元のコピーに書いたものがあとで食い違います。顧客管理システムを選ぶときは、何人が使うのか、担当者ごとにログインを分けられるか、誰がいつ何を変えたかが残るかを、まず確かめてください。人数が増えたときに費用がどう変わるかも、ここで見ておくとよいと思います。

### 2. 誰が、いつ入力するか

システムを入れても、入力されなければ台帳は空のままです。外回りの営業がその日のうちに打ち込めるのか、電話の合間に結果を残せるのか、事務の人がまとめて転記するのか。今エクセルに書いている人が、同じか少ない手間で続けられるかを、1日の流れに当てはめて考えてみてください。機能の数より、ここのほうが大事だと考えています。

### 3. お客様とのやり取りが、どこから来るか

残したいのは連絡先だけでなく「前に何を話して、次に何をするか」で、そのやり取りがどこから来るかで向いているシステムが変わります。訪問や打ち合わせが中心なら日報や議事メモ、電話をかける営業なら架電の結果、LINE公式アカウントで相談を受けているならLINEのトーク、というように、やり取りが生まれる場所から台帳に入る道があるかを見てください。

### 4. 今の台帳を取り込めるか、あとで書き出せるか

エクセルの台帳はCSVで保存できるので、移るときはCSVを取り込めるかが手間を左右します。見出しの名前が多少違っていても列を合わせられるか、文字コード（エクセルの既定で保存したCSVは Shift_JIS のことが多い）を気にせずに読めるか、同じ会社が二重に入っていたらどう扱うかを確かめておくと安心です。

あとで書き出せるかも大事です。別のシステムに移るときにCSVで持ち出せれば、一から入れ直さずに済みます。

### 5. データをどこに置くか

顧客の情報をクラウドのサービスに預けるか、自社で契約しているサーバーに置くか、という選び方もあります。クラウドは置き場所の用意やバックアップを任せられるのが良いところで、自社のサーバーに置く（オンプレミス）と、データがどこにあるのかを自分たちで説明でき、人数が増えても月額が積み上がらない、という良さがあります。その代わり、サーバーの用意とバックアップは自社の仕事になります。社内の決まりで顧客の情報を社外に置けないこともあるので、最初に確かめてください。

## 使い方で分ける、当社の顧客管理システム

当社では、顧客管理のシステムを「全部入り」の1本ではなく、使い方ごとに分けて開発しています。どれも PHP と SQLite だけで動き、MySQL などを用意せずに自社のレンタルサーバーへフォルダごと置けます。月額のかからない買い切りで、ソースコード一式をお渡しします（MIT ライセンス）。上の3番目、やり取りがどこから来るかで選ぶと分かりやすいと思います。

### 訪問・打ち合わせの日報から台帳を起こす：Kurage CRM Agent

営業がその日の日報を普段どおりの文章で書いて投げると、AIが会社・商談（ステージ・金額・次のアクション）・活動の記録に分けて「下書き」を作り、管理者が承認キューで中身を見て1タップで台帳に反映するシステムです。営業の手間は文章を書くことだけなので、上の2番目の「誰が入力するか」で困っている会社に向いています。

AIが台帳を直接書き換えることはなく、台帳に書けるのは人の承認だけです。AIが読み取った日付や金額はプログラムがデータベースと突き合わせて確かめ、承認の画面で手で直すこともできます。商談はかんばんで並び、ステージ別の金額なども集計されます。日報は画面のほか、外部APIからメールの転送やチャットとの連携でも投げられます。

AIはお客様が契約する OpenAI 互換のAIサービスを設定して使います。CSVの取り込みは無く、台帳は日報から少しずつ起きていく形です。動作環境は PHP 7.0 以上です。作った経緯は[入力ゼロCRMの開発記録](https://exbridge.jp/vibeblog/2026-08-19-kcrmagent-nyuryoku-zero.html)に書きました。

- [Kurage CRM Agent の製品ページ](https://kappstore.exbridge.jp/app.php?id=f6fab083d826739f#ref=vibeblog-kokyaku-kanri-system)
- [Kurage CRM Agent のデモ](https://proto.exbridge.jp/kcrmagent/)（パスワード demo2026。例文のボタンからAIに起票させ、承認キューの動きを見られます）

### LINE公式アカウントで受けた相談を、人ごとに記録する：Kurage LINE CRM

店舗やサロン、工務店、士業の事務所などで、LINE公式アカウントを相談の窓口にしている場合のシステムです。LINEの管理画面では、この人が誰で、前に何を約束したかが残りにくく、表示名もニックネームのことがあります。そこで、相談してきた人ごとに1枚のノートと、本名・会社名・電話などの連絡先の欄を持ちます。

画面は3列で、左が相談者の一覧、中がその人とのトーク履歴、右がノートと連絡先です。対応済みにした相手でも、新しいメッセージが届けば自動で「未対応」に戻って一覧の上に上がるので、返したつもりで止まっている相談を見落としにくくなります。

なお、LINEのアプリや管理画面から返した内容は、このシステムには記録されません。また、担当者ごとのログインは付いておらず、複数人で使うときは同じパスワードを共有する形です。対象は1対1のトークで、動作環境は PHP 7.0 以上と HTTPS です。

- [Kurage LINE CRM の製品ページ](https://kappstore.exbridge.jp/app.php?id=0e723e981c922df6#ref=vibeblog-kokyaku-kanri-system)
- [Kurage LINE CRM のデモ](https://proto.exbridge.jp/klcrm/)（パスワード demo2026）

### 電話をかける営業の架電リストから顧客にする：Kurage テレアポCRM・SFA

テレアポやインサイドセールスで、エクセルの架電リストを使っている会社向けです。今のエクセルの台帳をそのまま移したい場合は、4つのうちこれがいちばん移りやすいと思います。CSVは UTF-8 でも Shift_JIS でも読め、見出しの名前から列を探すので、列の順番を合わせ直す必要はありません。「株式会社」と「（株）」などの表記の揺れをそろえ、同じ電話番号か、同じ社名と郵便番号の先は重複として飛ばします。

「続けて架電」で、期限の来た再コール、未着手の先の順に1件ずつ出て、結果と次にかける日を残すと次へ進みます。アポが取れると自動で顧客になり、商談はかんばんで追えます。担当ごと・日ごと・リストごとに架電数・通話数・アポ数・アポ率を集計し、担当者は人ごとにログインを分けられます。1リスト9万件でも一覧は重くなりません。

電話そのものは今お使いの電話でかけ、結果を残す形です。書き出すCSVはオープンソースのCRMである EspoCRM や Krayin の列名に合わせてあり、会社が大きくなったときにも移りやすくしています。動作環境は PHP 8.1 以上です。詳しくは[テレアポ営業のCRM・SFAの記事](https://exbridge.jp/vibeblog/2026-11-03-kcallcrm-teleapo-crm-sfa-kaikiri.html)をご覧ください。

- [Kurage テレアポCRM・SFA の製品ページ](https://kappstore.exbridge.jp/app.php?id=0931d2dfecffc022#ref=vibeblog-kokyaku-kanri-system)
- [Kurage テレアポCRM・SFA のデモ](https://proto.exbridge.jp/kcallcrm/)

### いま進んでいる商談を追い、次の提案をAIと考える：Kurage Deal Desk

顧客の台帳は別にあって、困っているのは「どの商談が止まっているか」「次に何をするか」のほうだ、という会社向けの案件管理・商談管理のシステムです。顧客の台帳は持たず、お客様のメールアドレスを鍵にして商談を作ります。

打ち合わせのメモや届いたメールの本文を貼ると、AIが日付・次にやること・期日を入れた記録の下書きを作り、担当者が承認したときだけ記録に入ります。商談の記録と自社の製品の情報（ナレッジ）を根拠に次の提案をAIに相談でき、答えには出典が付きます。かんばんでは、期日の切れた商談と、しばらく動いていない商談に色が付きます。

AIはお客様が契約するAIサービスか、自社で動かすローカルのAI（Ollama など）を設定して使い、無くても記録とかんばんは使えます。お使いのCRMとは、CSVの書き出し、API、Webhook でつなぎます。動作環境は PHP 8 です。

- [Kurage Deal Desk の製品ページ](https://kappstore.exbridge.jp/app.php?id=63000166082c7a26#ref=vibeblog-kokyaku-kanri-system)
- [Kurage Deal Desk のデモ](https://proto.exbridge.jp/kdealdesk/)（顧客はすべて架空で、データは1日で元に戻ります）

## どれを選べばいいか迷ったら

迷ったときは、今エクセルに書いている人が、1日のどの場面で書いているかを思い浮かべてください。訪問から戻って日報を書いているならCRM Agent、LINEの相談に返しているならLINE CRM、電話をかけ続けているならテレアポCRM・SFA、商談の進み具合を追っているならDeal Desk、という分け方になります。どれもデモで動きを確かめられます。他のシステムはまとめて [Kurage App Store](https://kappstore.exbridge.jp/#ref=vibeblog-kokyaku-kanri-system) に並べています。

## よくある質問

**Q. エクセルの顧客台帳は、そのまま取り込めますか？**

当社の4つのうち、CSVの取り込みが入っているのは Kurage テレアポCRM・SFA です。エクセルの台帳をCSVで保存すれば、UTF-8 でも Shift_JIS でも読み込め、見出しの名前から列を探します。ほかの3つには、エクセルの台帳をまとめて取り込む機能はありません。

**Q. 人数が増えると費用は増えますか？**

自社のサーバーに置く買い切りなので、月額はかからず、担当者が増えても追加の料金はありません。CRM Agent と Deal Desk でAIを使う場合は、お客様が契約するAIサービスの利用料が別にかかります。

**Q. AIが勝手に顧客の台帳を書き換えることはありませんか？**

CRM Agent も Deal Desk も、AIが作れるのは下書きまでで、台帳や記録に入るのは人が承認したときだけです。テレアポCRM・SFA と LINE CRM にはAIそのものは入っておらず、Claude Code などから使う口（MCP）があります。テレアポCRM・SFA のMCPは読むことと架電の結果の記録までで、LINE CRM はお客様のLINEへ送る操作を既定で無効にしてあり、参照だけにする設定もあります。

**Q. 将来、別のCRMに移ることはできますか？**

テレアポCRM・SFA はCSVを EspoCRM や Krayin の列名で書き出せ、Deal Desk も商談をCSVで書き出せます。CRM Agent と LINE CRM には画面からCSVを書き出す機能はありませんが、データはどれも自社のサーバーの中の SQLite のファイルにあり、そのフォルダごと手元で持っておけます。
