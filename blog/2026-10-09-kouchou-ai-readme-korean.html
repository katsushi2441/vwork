Claude Code活用事例：広聴AIの韓国語版READMEを1時間でPRに——OSSコントリビュートの手順

2026-10-09

名古屋でAIシステム開発の会社をやっています。10月9日の朝、デジタル民主主義2030（DD2030）のSlackを読んでいて、広聴AIの開発者の西尾さんが前日に残した「メモ: 韓国語版のREADMEを作る」という一行を見つけました。READMEの翻訳なら、すぐに形にできると思い、その場で取りかかりました。Issueを立ててPRを出し、Slackで知らせるまで、およそ1時間でした。

  • PR #959 docs: 韓国語版のREADME（README.ko.md）を追加
  • Issue #958

1. なぜ韓国語版なのか

広聴AIは、たくさんの意見を読み込んで、話題ごとのまとまりに分けて見せるオープンソースのソフトウェアです。最近は、韓国語で書かれた短い意見を日本語の意見として分析する使い方も試されていて、Slackでもその話が出ていました。韓国の方が広聴AIを知って最初に開くのはGitHubのREADMEなので、そこが日本語だけだと入口で止まってしまいます。

2. 先に確かめたこと

手を動かす前に、次の3つを確かめました。

  • 本家のリポジトリに、韓国語版のREADMEがまだ無いこと
  • 同じ作業をしているIssueやPRが無いこと（誰かと重なると、お互いの手間になります）
  • プロジェクトの、AIエージェントで貢献するときのルール

広聴AIには「Claude Code / Codex でIssueに着手してからPRを提出するまで」の案内があり、Issueを確かめてから着手すること、PRには検証した結果と、確かめていないことを分けて書くこと、レビューの依頼やSlackでの連絡はAIが勝手にしないこと、などが決められています。今回もこれに沿って進めました。

3. やったこと

  1. 本家の最新の main から作業用のブランチを作りました
  2. Issue #958 を立てて、やることを書きました（README.ko.md の追加、言語の切り替えリンク、日本語版が正という注記）
  3. README の全文、約240行を韓国語に訳しました
  4. 日本語版と韓国語版の両方の冒頭に「日本語 | 한국어」の切り替えリンクを入れました
  5. 韓国語版の冒頭に「日本語版が正で、リンク先のガイドはほとんど日本語」と一言添えました
  6. 公開フォークに上げて、PR #959 を出しました
  7. 西尾さんのメモのスレッドに、PRを出したことを返信しました

4. AIで訳すときに、機械で確かめたこと

READMEの翻訳で一番困るのは、訳文がそれらしく読めても、コマンドや環境変数の名前、URLが原文から少しずれていることです。読んだだけでは気づきにくく、そのまま手順どおりに打った人がつまずきます。そこで、原文と訳文を並べて、次の数がそろっているかをスクリプトで数えました。

  • 見出し：どちらも24
  • コードブロック：どちらも8
  • URL：どちらも同じ18種類
  • コマンド・環境変数名・ファイルのパス（docker compose up、OLLAMA_HOST_PORT など）：すべて一致

もう1つ、日本語の書き方がそのまま残っていないかも見ました。最初の訳では「」や「・」が残っていたので、韓国語でふつうに使う‘’や読点に直しました。一方で、CONTRIBUTING.md へのリンクの #コードを書かずに参加する は、リンク先の見出しが日本語なので、あえてそのままにしています。

5. 確かめていないこと

韓国語として自然かどうかは、話者の方に見てもらわないと分かりません。PRとSlackには、ネイティブのチェックはできていないので、どなたか見ていただけると助かる、と正直に書きました。訳の正しさを、自分で「確認済み」とは書いていません。

6. 前回の貢献とのつながり

広聴AIへの貢献は今回が2回目です。10月6日には、パソコンにすでに Ollama が入っていると広聴AIのローカルLLMが起動しない問題を見つけ、Issue #951 と PR #952 を出しました。こちらは同じ日のうちにマージされています。どちらも、自分で使ってつまずいたところや、開発者の方のメモから、小さく直せるものを選んで出しています。

途中で気をつけたところ

  • ルールを先に読む：AIエージェント向けの案内があるプロジェクトでは、それを読まずにPRを出すと、レビューする方の手間を増やします
  • 数えられるものは数える：訳文の良し悪しは読んで判断するしかありませんが、URLやコマンドが一致しているかは機械で確かめられます
  • できていないことを書く：ネイティブのチェックをしていないことは、PRの本文に分けて書きました

よくある質問

広聴AIとは何ですか？

デジタル民主主義2030が開発しているオープンソースのソフトウェアで、パブリックコメントやアンケートの自由記述のような、たくさんの意見を読み込んで、話題ごとのまとまりに分けて見せます。自治体や政治家の実務に合わせて改良が進められています。

AIで翻訳したREADMEをPRに出してもよいのですか？

広聴AIは、Claude Code や Codex を使った貢献の手順を公式に案内しています。大事なのは、プロジェクトのルールに沿うことと、検証した結果と確かめていないことを分けて書くことです。今回もコントリビューターライセンス契約（CLA）に同意したうえで出しています。

翻訳のどこを機械で確かめられますか？

見出しの数、コードブロックの数、URL、コマンド・環境変数名・ファイルのパスです。ここがずれると手順どおりに動かなくなるので、まずここを原文とそろえます。文章が自然かどうかは、話者の方に見てもらう必要があります。
