名古屋でシステム開発をしている小嶋です。

AIで業務を効率化したい、自動化したいという相談が増えました。よく聞くのが、「Copilot や Claude Code を入れてみたけれど、業務そのものはあまり変わらない」という声です。

この1年、お客様の会社と自社で、AIと一緒に仕事をする仕組みを作ってきました。そこでわかったのは、AIで業務を自動化するには、AIの道具を入れるだけでは足りず、AIが業務システムを直接扱える土台が要るということです。この記事では、その土台を「AIシステム基盤」と呼んで、考えをまとめます。

## 業務支援と業務自動化は違う

生成AIを入れてすぐにできるのは、業務支援です。

- 文章の下書きを作る
- 調べものをまとめる
- プログラムを書く
- 表やメールの文面を整える

どれも、人の作業をAIが手伝う形です。AIが作ったものを、人が業務システムに貼り付けたり、送ったりします。

業務自動化は、その先です。受注を受け付けて仕入先に発注する、メールを読んで返事を出し、片付ける、会計に記帳する。業務そのものをAIに任せるには、AIが受注の記録、メール、会計といった業務システムを、直接読んで書けなければなりません。

Copilot や Claude Code は、AIの側の道具です。AIが触れる業務システムが無ければ、AIは手伝うことしかできません。

## 化学分析会社で約40の業務システムを作った

このことに気づいたのは、ある化学分析会社での仕事でした。

4か月、1か月30時間、合わせて120時間で、約40の業務システムを開発しました。基幹業務を除いた、技術部門・営業部門・総務部門のほぼすべての業務を支える仕組みです。

- グループウェア
- 文書管理システム
- 全文検索エンジン
- 企業内のAIチャットボット
- 報告書の作成アシスト
- 報告書のチェック
- 測定器が出したグラフを表に変えるシステム
- 見積書の作成アシスト
- 入札情報や官報のチェック
- 障害の分析
- 障害の検知システム
- ネットワークの運用支援
- 人事管理システム
- X投稿の支援、ブログ、CMS

120時間で40の業務システムを作れたのは、開発そのものをAIと一緒に進めたからです。そして作っていくうちに、作ったシステムどうしがつながり、AIがその上で仕事をできるようになっていきました。報告書の作成アシストが文書管理システムの過去の報告書を読み、チャットボットが全文検索エンジンで社内の資料を探す、という具合です。

一つひとつのシステムより、AIが業務のデータに触れられる土台がそろったことのほうが、効いていると感じました。

## 自社の業務も、すべてAIと回している

当社でも、自分が行う業務のシステムを、すべてAIが操作できる形にしました。

- **会計・基幹業務**（kverp）
- **メール**（kmail）：受信箱を読み、返事を作り、送ったあとに振り分ける
- **ネットショップ**（kvcart で動かしている X-Direct）：受注、仕入先への発注書、納期と振込先の案内、出荷の連絡、商品の登録
- **データベースの窓口**（kdbagent）：決められた表だけを、AIが読み書きする
- **Google 広告と Merchant Center**：日別の費用の確認、入札の調整、不承認の商品の手直し
- **ブログ（vibeblog）と Kurage の動画**：記事の公開、ショート動画、YouTube への投稿

今は、受注から仕入先への発注、お客様へのご案内、出荷の連絡、広告の調整、記事と動画の公開まで、ほぼすべての業務をAIと一緒にしています。人がするのは、判断と確認、そして「送って」「直して」の指示です。

## AIシステム基盤とは

ここまでの経験から、AIで業務を自動化するための土台を「AIシステム基盤」と呼ぶことにしました。中身は次のようなものです。

1. **業務システムがそろっている**：業務のデータが、紙や個人のパソコンではなく、システムの中にある
2. **AIが操作できる入口がある**：業務システムごとに、AIが読み書きできる入口（APIやMCP）がある。触れてよい範囲も決めておく
3. **記録が残る**：AIがいつ何をしたかが残り、人があとから確かめられる
4. **止まらずに動く**：受注の取り込みや定期の処理が、夜も休日も動き続ける

AIの道具（Copilot や Claude Code）は、この上に乗るものです。土台があれば、使うAIを替えても業務は回り続けます。

## 置き場所は Linux がよい

AIシステム基盤を動かす場所は、Linux を標準にしています。当社も、化学分析会社でも Linux で動かしています。

- 夜も休日も止まらずに動かせる
- すべてコマンドで扱えるので、AIが自分で状態を調べて、直して、また確かめられる
- 業務システムの部品（Python、PHP、データベース、MCP のサーバーなど）が、そのまま動く
- 遠くから保守できるので、改修を続けやすい

社員の方が使うパソコンは、Windows のままで構いません。ブラウザから業務システムを開くだけです。

## AI-IT顧問契約の中で、AIシステム基盤を作りませんか

AIシステム基盤は、一度に全部を作るものではありません。業務を一つずつ、AIが扱える形にしていくものです。化学分析会社でも、1か月30時間のペースで4か月かけて、約40のシステムを順に作りました。

そこで当社では、AI-IT顧問契約の中で、お客様の会社のAIシステム基盤を作っていくことを提案しています。毎月、困っている業務を一つずつシステムにし、AIがその業務を扱えるようにしていきます。

「Copilot を入れたけれど、業務が変わらない」という会社ほど、AIの道具ではなく、AIが触れる業務システムの側に手を入れると、変わり始めると考えています。

## よくある質問

### Copilot や Claude Code を入れれば、業務は自動化できますか？

文章を書く、調べる、プログラムを書くといった業務支援はできます。ただ、受注や発注、メールの処理、会計のように業務そのものをAIに任せるには、AIが業務システムを直接読み書きできる土台（AIシステム基盤）が要ります。

### AIシステム基盤とは何ですか？

AIで業務を自動化するための土台です。業務のデータがシステムの中にあり、AIが読み書きできる入口があり、AIのしたことが記録に残り、止まらずに動く。この4つがそろった状態を指しています。

### どのくらいの期間で作れますか？

ある化学分析会社では、4か月、1か月30時間、合わせて120時間で約40の業務システムを作りました。業務を一つずつ順にシステムにしていく形です。

### Windows のパソコンでも動きますか？

社員の方が使うパソコンは Windows のままで構いません。AIシステム基盤を動かす場所は、止まらずに動き、AIが操作しやすい Linux をおすすめしています。
