名古屋でシステム開発をしている、株式会社エクスブリッジの小嶋です。

請求書の作成と発行は、Excelのひな形で作ってPDFにし、メールに添付して送る、という形で続けている会社が今も多いと思います。それで回っているうちはよいのですが、件数が増えたり、インボイス制度で記載事項を気にするようになったり、入金の確認に時間を取られたりして、請求書の発行システムを探し始める方がいらっしゃいます。この記事では、請求書の作成・発行のシステムを選ぶときに見るところを、インボイスの記載事項、発行から入金確認まで、PDFとメールの送り方、の順にまとめます。そのあとで、当社が開発して Kurage App Store で販売している、自社サーバーで動かす3つのシステムを紹介します。

## 1. インボイス（適格請求書）の記載事項が請求書のどこに出るか

まず確かめたいのは、作った請求書がインボイス（適格請求書）の体裁になっているかです。当社の請求書システムを設計したときは、次の6つを請求書のどこに出すかを1つずつ決めました。

- 発行する事業者の名称と、適格請求書発行事業者の登録番号
- 取引の年月日（発行日）
- 取引の内容（明細の品目）
- 税率ごとに分けた金額と、適用する税率
- 税率ごとの消費税の額
- 請求書を受け取る事業者の名称（宛名）

システムを比べるときは、この6つが実際のPDFにどう出るかを、見本を1枚出して確かめるのが確実です。あわせて見ておきたいのが、消費税の端数の扱いです。明細の行ごとに消費税を計算して足し合わせると、税率ごとにまとめて計算した場合と1円ずれることがあります。たとえば999円の品目が2行なら、まとめて計算すると小計1,998円に対して消費税は199円ですが、行ごとに計算すると99円＋99円で198円になります。インボイスでは税率ごとに1回だけ端数処理をするので、システムがどちらの計算をしているかは確かめておくところです。

登録番号の扱いも見ておいてください。登録番号をまだ持っていない事業者が請求書を出すこともあります。その場合に、番号の欄が空のまま印字されたり、見本の番号が残ったりしないかを確かめておくと安心です。

## 2. 発行してから入金を確認するまでの流れ

請求書の仕事は、作って送れば終わりではありません。送ったあとに、払っていただけたかを確かめ、期限を過ぎたものに気づき、必要なら領収書を出すところまでが一続きです。

選ぶときは、請求書番号が自動で振られるか、未入金・入金済み・期限超過が一覧で分かるか、入金を記録したときにお客様へお礼の連絡を出せるかを見てください。クレジットカードで払っていただく仕組みを付けるなら、決済が本当に完了したことを、システムがどう確かめているかも大事です。支払いボタンはお客様のブラウザの中で動くので、「支払いが終わった」という知らせをそのまま信じる作りだと、実際には払われていないのに入金済みになるおそれがあります。

もうひとつ、「こちらから請求書を出す」のか、「お客様がサイトから申し込んで、それに対して請求書を出す」のかで、合うシステムが変わります。価格の決まったサービスを申し込んでいただく形なら、注文の受け付けから請求書の発行までがつながっているほうが手間が少なくなります。

## 3. 請求書PDFをメールに添付するか、URLで送るか

請求書の送り方には、大きく分けて、PDFをメールに添付して送る形と、請求書を見られるページのURLをメールで送る形があります。

添付は、受け取る側にとっていちばんなじみがあり、そのまま保存できるのが良いところです。気をつけたいのは、宛先を間違えたときです。添付したPDFは相手のメールボックスに残るので、送ったあとで取り消すことができません。請求書には取引先の名前と金額が書いてあるので、誤送信がそのまま情報の漏れになります。

URLで送る形は、受け取った方がページを開いてPDFを取得したり、そのまま支払ったりできます。推測されにくいURLにしておくのが前提で、さらに宛先のメールアドレスを入力しないと開けないようにしておけば、URLが違う人に届いても中身は見えません。そのぶん、受け取る方にはひと手間増えます。どちらが合うかは、取引先の経理の方の受け取りやすさと、誤送信をどこまで重く見るかで決めてください。

## 4. データの置き場所と、件数が増えたとき

クラウドの請求書サービスは、すぐに使い始められ、会計ソフトとの連携などが充実しているものが多いのが良いところです。一方で、取引先の名前や金額を外に預けたくない、発行件数や使う人数で費用が変わるのを避けたい、という会社には、自社のサーバーに置く「オンプレミス」のシステムが選択肢になります。自社サーバーに置く形なら、件数や使う人数で費用が変わらず、使うのをやめてもデータは手元に残ります。

## 自社サーバーで動かす、請求書・領収書・注文受付の3つのシステム

当社が開発した3つのシステムは、どれもPHPが動くレンタルサーバーに置いて使います。データベースは使わず、データはファイルに書きます。Composer や npm も要らず、FTPで上げれば動きます。Claude Code などのAIエージェントに渡せば設置まで進められる手順書（CLAUDE.md・AGENTS.md・INSTALL.md）も同梱しています。

### 請求書を発行して、入金まで管理する「kbilling」

- [請求書ソフトをオンプレミスで・発行から集金まで（kbilling）の製品ページ](https://kappstore.exbridge.jp/app.php?id=15abb025dc2ee4f6#ref=vibeblog-seikyusho-sakusei-hakko)

kbilling は、請求書をPDFで発行し、お客様ごとのURL（32桁）をメールで送るシステムです。お客様はログインせずにそのページを開き、請求書のPDFを取得して、銀行振込かPayPal（クレジットカードも使えます）で支払えます。明細は最大12行で、値引きの行も書けます。消費税は10%・8%・0%から選び、税率ごとに1回だけ端数処理します。請求書番号は自動で振られ、PDFには上の6つの記載事項が出ます。登録番号は設定したときだけ印字するので、未登録のうちに架空の番号が載ることはありません。

PayPalの支払いは、ブラウザからの知らせを信じず、PayPalのAPIに直接問い合わせて、決済の確定・通貨・金額・請求書IDの4つがすべて合ったときだけ入金として記録します。偽の決済を弾くテストも同梱しています。銀行振込は、管理画面で「入金確認」を押すと入金済みになり、お客様にお礼のメールが送られます。一覧では未入金・期限超過・入金済みが分かります。請求書のページを開くときに宛先のメールアドレスの入力も求めるように、設定で切り替えられます。

入っていないものもあります。1枚の請求書で選べる税率は1つです。見積書・納品書の発行、定期的な請求の自動発行、会計ソフトとの自動連携、銀行の入出金明細の取り込み、電子帳簿保存法のタイムスタンプには対応していません。

- [kbilling のデモ](https://proto.exbridge.jp/kbilling/#ref=vibeblog-seikyusho-sakusei-hakko)（パスワードは demo2026 です。デモではメールは送られません）
- [kbilling を開発したときの記事（PayPalの入金をどう確かめているか）](https://exbridge.jp/vibeblog/2026-08-06-kbilling-invoice-collect.html#ref=vibeblog-seikyusho-sakusei-hakko)

### 入金のあとに領収書をPDFで出す「kinvoice」

- [領収書をPDFで発行してメール送信（kinvoice）の製品ページ](https://kappstore.exbridge.jp/app.php?id=61febea74f9c74b0#ref=vibeblog-seikyusho-sakusei-hakko)

kinvoice は、入金をいただいたあとの領収書を担当します。顧客名・メールアドレス・税込の金額・発行日・但し書きを入れて発行すると、ダウンロード用のURLをメールで送ります。PDFは添付しません。URLを開いたときに宛先のメールアドレスの入力を求め、2つがそろわないと開かず、10回間違えるとロックします。領収書には税率ごとの内訳を出し、端数が出ても内訳の合計が税込の総額に一致するようにしています。登録番号は設定したときだけ印字し、未設定なら「記載しておりません」と出ます。電子で交付するので収入印紙は不要である旨も印字します。発行した領収書は送信の履歴に残り、そこから再送できます。

- [kinvoice のデモ](https://proto.exbridge.jp/kinvoice/#ref=vibeblog-seikyusho-sakusei-hakko)
- [kinvoice を開発したときの記事](https://exbridge.jp/vibeblog/2026-08-05-kinvoice-foundation.html#ref=vibeblog-seikyusho-sakusei-hakko)

### 注文フォームから請求書・支払いまでつなぐ「kpaylink」

- [注文フォームから請求書・決済まで（kpaylink）の製品ページ](https://kappstore.exbridge.jp/app.php?id=5b55bb2c808eead4#ref=vibeblog-seikyusho-sakusei-hakko)

kpaylink は、価格の決まった商品やサービスの注文ページを、設定ファイル1枚で立ち上げるシステムです。お客様がログインせずに請求先を登録すると、その注文に対して番号付きの請求書PDFが発行され、銀行振込かPayPalで支払えます。注文ごとのURL（16桁）が、そのままお客様の控えになります。商品名・金額・税率・社名・登録番号・振込先などはすべて設定ファイルで変えられ、商品が複数あれば、フォルダを分けて設定を変えるだけで何ページでも並べられます。PayPalの入金は、kbilling と同じようにPayPalのAPIに問い合わせて確かめてから記録します。カート機能や在庫の連動、送料の計算、定期課金は入っていません。営業がこちらから請求書を出すなら kbilling、サイトから申し込みを受けるなら kpaylink、と考えてください。

## よくある質問

**Q. 請求書を作成・発行するシステムは、インボイス制度に対応していますか？**

kbilling の請求書PDFには、発行する事業者の名称と登録番号、発行日、明細の品目、税率ごとの金額と適用税率、消費税の額、宛名が出ます。消費税は税率ごとに1回だけ端数処理します。登録番号は設定したときだけ印字します。

**Q. 10%と8%の品目が混ざった請求書は出せますか？**

kbilling は、1枚の請求書に1つの税率を選ぶ作りです。税率の違う品目は、請求書を分けて発行してください。

**Q. 請求書を受け取るお客様に、アカウントを作ってもらう必要はありますか？**

ありません。kbilling は請求書ごとのURLを、kpaylink は注文ごとのURLをお送りするだけです。kbilling は設定で、ページを開くときに宛先のメールアドレスの入力を求めることもできます。

**Q. PDFをメールに添付して送ることはできますか？**

kbilling と kinvoice は、誤送信が情報の漏れにならないように、PDFを添付せずURLを送る作りにしています。お客様はそのページからPDFを取得できます。

**Q. 見積書や納品書も作れますか？**

kbilling には見積書・納品書の発行は入っていません。請求書は kbilling、入金後の領収書は kinvoice、サイトからの注文受付と請求書は kpaylink が担当します。
