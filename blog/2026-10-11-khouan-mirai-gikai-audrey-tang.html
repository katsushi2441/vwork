オードリー・タンとみらい議会から考えた、法案AIインタビュー「khouan」の構想——Join・いどばた・AIインタビューを調べて分かったこと

2026-10-11

名古屋でAIシステム開発の会社をやっています。デジタル民主主義の道具を一つの流れに並べた資料を作ったあと、Claude Code と一緒に「オードリー・タンさんは何を実現したのか」から調べ直しました。調べるうちに、台湾のJoin、DD2030のいどばた、チームみらいのみらい議会とAIインタビューへと話がつながり、最後は新しいシステム「Kurage 法案AIインタビュー（khouan）」を作り始めることになりました。その経緯を、調べた順に書きます。

1. オードリー・タンさんが実現したこと

オードリー・タンさんは、台湾の市民技術者のコミュニティ g0v の中心人物の一人で、2016年からデジタル担当の大臣、2022年からは新しくできたデジタル発展部の初代大臣を務めました。

主張の中心は、分断はテクノロジーで乗り越えられる、ということです。多数決で勝ち負けを決めるのではなく、立場の違う人どうしが一致できる点を探す。2024年にグレン・ワイルさんと出した『Plurality（多元性）』では、テクノロジーで国家の権限を社会の側へ分散させる道を説いています。

実現したことは、次のようなものです。

  • vTaiwan：法令づくりへの市民参加の場。2015年の配車アプリの規制では、Pol.is で見つけた立場をこえた合意点が、規則づくりに使われました。
  • Join：市民が政策を提案する場。
  • マスクマップ：コロナの初期に、薬局ごとのマスクの在庫を地図に出しました。

日本の国会でオードリー・タンさんにふれた発言は46件ありました。ただ、ほとんどはマスクマップの話で、合意形成や『Plurality』の考え方まで議論した発言はわずかでした。

2. Joinといどばたは、似ているが別物

次に、Joinを参考に DD2030 の「いどばた」ができたのかを調べました。

いどばたのリポジトリを全部読みましたが、Join・台湾・vTaiwan・Pol.is にふれた箇所はありませんでした。一方で、DD2030 の周りの資料には、2025年1月の台湾視察や、「台湾の JOIN のような市民参加型の政策形成を日本で実装する」という目標が出てきます。問題意識は近いが、写したものではない、と読むのが正確です。

仕組みははっきり違います。

  • Join は「制度」です。60日で5,000人の賛同が集まると、担当の省庁は2か月以内に回答しなければなりません。ただ、開設から5年で9,000件を超える提案のうち、5,000人に届いたのは202件、実際に採用されたのは39件という指摘もあります。
  • いどばたは「道具」です。AIとの対話で意見を集め、課題と解決策を整理して、論点や政策の案を作ります。使う側に回答の義務はありません。

どちらにも、賛否の割れ方を計算して合意点を出す仕組みはありません。

3. いどばたは、ほぼチームみらいで使われている

いどばたがどこで使われているかを調べると、中心はチームみらいでした。「みらいいどばた会議」と、マニフェストへの修正の提案（2,000件近く）に使われています。立憲民主党の採用の発表や、中野駅の再開発の実証実験もありましたが、いま動いていると確かめられたのはチームみらいの分だけでした。

GitHub の写し（フォーク）は51件ありましたが、ほとんどは個人のもので、自治体や団体の名前のものはありませんでした。本体の更新も、2026年7月から止まっています。

4. チームみらいは、いどばたとみらい議会をどう使い分けているか

チームみらいの使い方を整理すると、こうなりました（使い分けを一つの文書で説明した資料は無く、ここは私たちの読みです）。

  • いどばた：チームみらい自身の政策をつくる
  • みらい議会：国会の法案ごとに、解説して、意見を聞く。2026年3月に AIインタビュー、6月に意見を話題に束ねる機能が加わりました
  • 広聴AI：集めた声を地図にする
  • 広聴本部：2026年9月に、これらを束ねる組織として立ち上げ。10月には「みらい版Pol.is」をこれから作ると発表

AIインタビューは別の道具ではなく、みらい議会の中の機能でした。

5. みらい議会のソースコードを読んで分かったこと

みらい議会は GitHub で公開されています。中身を読むと、法案の解説（やさしい解説への切り替え・AIへの質問）、党の賛否の表示、AIインタビュー（同意の画面・本人が確かめるまとめ・「参考になる」の反応）、意見の一覧と話題のページ、データの公開、管理画面のインタビューの試し運転まで、よく作り込まれていました。

一方で、2025年9月の最初の構想の資料にあって、まだ入っていないものがありました。

  • 法案や論点への賛否の投票と、意見の対立の見え方
  • 議員ごとの投票の記録と、発言・答弁の履歴（議員のトラッキング）

6. その2つは、当社にすでにあった

この2つは、当社がすでに動かしているものでした。

  • 国会トラッカー：法案742本について、要約（元の文と数字・日付を照らし合わせたもの）、審議の経過、国会での質疑と答弁7,062件、会派ごとの賛否を並べています。
  • 論点AIマップ：すでにある声から、話題の地図と論点を作ります。
  • 合意形成AI（Pol.is 互換）：賛否の割れ方と、立場をこえた合意点を出します。

足りないのは、「法案ごとに意見を聞く」ところだけでした。

7. khouan の構想

そこで、新しい製品「Kurage 法案AIインタビュー（khouan）」を作ることにしました。名前は、検索や対外の名前が後から割れないよう、作る前に決めました。

khouan は、論点AIマップや合意形成AIと同じく、別の製品として作り、デモを動かしながら、国会トラッカーの法案のページに組み込みます。

  1. 法案を解説する：国会トラッカーの法案の要約・審議の経過・質疑と答弁を使う
  2. 意見を聞く：法案ごとに AI が聞き手になり、答えに合わせて質問を重ね、最後に本人が確かめた「意見のまとめ」を残す
  3. 話題に束ねる：論点AIマップと同じ仕組みで、意見を話題に分ける
  4. 割れ方と合意点を出す：話題から賛否を問える論点を作り、合意形成AIに渡す

法案のページには、「この法案に意見を伝える」「みんなの意見」「どこで割れていて、どこで一致しているか」の3つの枠を足します。法案を読む、議員の質疑と答弁をたどる、自分の意見を伝える、みんなの意見の割れ方と合意点を見る、までが一つの流れになります。

AIは当社のサーバーで動かす生成AIを使い、最初はいまの臨時国会で審議中の法案から始めます。この記事を書いている時点では、作り始めたところです。動いたら、改めてこのブログで報告します。

調べてみて思ったこと

オードリー・タンさんの取り組みの中心は、声を集めて地図にすることではなく、立場の違う人が一致できる点を見つけて、政策に反映させるところにありました。日本では、声を集める道具は広がりつつあります。その先の「どこで一致できるか」と「誰が何を言ってきたか」を、法案という具体的な単位でつなげることが、次の一歩だと考えています。

よくある質問

オードリー・タンさんは何をした人ですか？

台湾のデジタル担当の大臣（2016年〜）、初代のデジタル発展部の大臣（2022〜2024年）を務めた人です。法令づくりへの市民参加の場 vTaiwan や、コロナの初期のマスクマップで知られ、立場の違う人どうしの合意点を探す考え方『Plurality（多元性）』を説いています。

みらい議会とは何ですか？

チームみらいが運営する、国会の法案をAIで分かりやすく解説し、AIインタビューで意見を聞き、意見を話題に束ねて見せるサイトです。ソースコードは GitHub で公開されています。

いどばたとみらい議会の違いは何ですか？

いどばたは DD2030 が作った道具で、チームみらいでは党自身の政策をつくるのに使われています。みらい議会はチームみらいが自分で作ったシステムで、国会の法案ごとに解説と意見の聞き取りをします。AIインタビューは、みらい議会の中の機能です。

khouan はみらい議会と何が違いますか？

法案を解説して意見を聞き、話題に束ねるところは同じ方向です。違いは、当社の国会トラッカーの「議員の質疑と答弁の記録」と、合意形成AIの「賛否の割れ方と合意点」を、法案のページで一つにつなぐところです。
